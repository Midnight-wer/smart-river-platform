 6. API 调用示例

powershell
$body = '{"username":"admin","password":"123456"}'
$response = Invoke-WebRequest -Uri "http://localhost:8084/api/v1/auth/login" `
-Method POST -ContentType "application/json" -Body $body -UseBasicParsing
$token = ($response.Content | ConvertFrom-Json).data.token
Write-Host "Token: $token"

powershell
$headers = @{ "Authorization" = "Bearer $token" }

 7. AI 检测模型

 7.1 漂浮物检测 API

**端点**：`POST http://localhost:8001/api/v1/ai/floating-objects/detect`

**请求体**：

json
{
"image_base64": "<Base64 编码的图片>",
"confidence_threshold": 0.5,
"return_visualization": true
}


**响应**：

json
{
"code": 200,
"message": "success",
"data": {
"image_width": 1918,
"image_height": 1080,
"total_count": 2,
"detections": [
      {
"class_id": 2,
"class_name": "bottle",
"class_name_cn": "瓶类",
"confidence": 0.873,
"bbox": { "x1": 100, "y1": 200, "x2": 150, "y2": 250 },
"color": "00d4ff"
      }
],
"demo_mode": false,
"visualization_base64": "<Base64 编码的可视化图片>"
  }
}


 7.2 检测类别定义

代码定义在 [river-ai/models/constants.py](./river-ai/models/constants.py))：

| ID | 英文名 | 中文名 | 颜色 |
|----|--------|--------|------|
| 0 | plastic | 塑料制品 | 00d4ff |
| 1 | foam | 泡沫制品 | ff9800 |
| 2 | bottle | 瓶类 | 4caf50 |
| 3 | branch | 树枝枯木 | 9c27b0 |
| 4 | grass | 水草藻类 | 8bc34a |
| 5 | trash | 其他垃圾 | f44336 |

 7.3 演示模式（DEMO MODE）

当真实模型 `floating_objects.onnx` 不存在时，AI 服务自动切换到演示模式：

- 使用 COCO 预训练 `yolov8n.pt`（80 类日常物品）
- 通过 [COCO_TO_FLOATING_MAPPING](./river-ai/services/floating_objects/service.pyL34-L83) 把 COCO 类别映射到河道漂浮物类别
- 未映射的 COCO 类别（如人、车、动物）会被过滤，避免误报
- 置信度阈值自动提升到 0.4 以减少误检
- 返回结果中 `demo_mode: true`

启动日志会显示明显的警告：


⚠️  进入过渡演示模式（DEMO MODE）
⚠️  使用 COCO 预训练模型 + 类别映射
⚠️  该模式精度有限，仅用于功能演示
⚠️  请尽快训练真实模型并放置到 models/production/floating_objects.onnx


 7.4 部署真实模型

　　　1.按 [漂浮物检测模型技术方案..md](./漂浮物检测模型技术方案..md) 完成数据采集、标注、训练
　　　2.把训练好的 ONNX 模型放到：


　　　e:\河道治理\river-ai\models\production\floating_objects.onnx


3. 重启 AI 服务即可自动切换到真实模型模式，**无需改代码**，`demo_mode` 会自动变为 `false`

 12. 常见问题

 12.1 PowerShell 脚本无法运行
**现象**：`无法加载文件 xxx.ps1，因为在此系统上禁止运行脚本`

**解决**：PowerShell 执行策略限制，所有命令直接调用可执行文件绕过：

powershell
 不要用：mvn
 改用：.\mvnw.cmd
 不要用：yarn dev
 改用：npx vite


 12.2 Maven 下载依赖 SSL 错误

**现象**：`PKIX path building failed: unable to find valid certification path to requested target`

**原因**：JDK 1.8.0_91 的 cacerts 证书库过旧，不信任 maven.apache.org 的证书。

**解决**：
　　　1.已配置阿里云镜像（见 [2.5 节](25-maven-镜像配置避免-ssl-证书错误)）
　　　2.打包时加 SSL 跳过参数：
powershell
.\mvnw.cmd clean package "-DskipTests" "-Dmaven.wagon.http.ssl.insecure=true" "-Dmaven.wagon.http.ssl.allowall=true" -q


 12.3 PowerShell 参数含 `=` 报错

**现象**：`Unknown lifecycle phase ".test.skip=true"`

**原因**：PowerShell 把 `=` 当参数分隔符。

**解决**：用引号包裹含 `=` 的参数：

powershell
 错误：.\mvnw.cmd clean package -Dmaven.test.skip=true
 正确：
.\mvnw.cmd clean package "-Dmaven.test.skip=true"


 12.4 后端启动报 "Invalid CUDA 'device=0'"

**现象**：AI 服务返回 500，提示 CUDA 不可用。

**原因**：CPU 版 PyTorch 不支持 CUDA。

**解决**：已在 [service.py](./river-ai/services/floating_objects/service.pyL143-L149) 自动回退 CPU，无需手动处理。日志会显示 `CUDA 不可用，自动回退到 CPU 推理`。

 12.5 ultralytics 配置目录权限错误

**现象**：`PermissionError: [WinError 5] 拒绝访问: 'C:\Users\Lenovo\AppData\Roaming\Ultralytics'`

**解决**：设置环境变量重定向到项目内：

powershell
$env:YOLO_CONFIG_DIR="d:\河道治理\river-ai\.ultralytics"


 12.6 uvicorn 字符串导入失败

**现象**：`Error loading ASGI app. Could not import module "main"` 或 `Import string "app" must be in format "<module>:<attribute>"`

**原因**：原配置 `uvicorn.run("main:app", reload=True)` 用字符串导入，相对路径找不到模块。

**解决**：已在 [main.py](./river-ai/services/main.pyL336-L343) 修改为直接传 app 对象 + 关闭 reload：

python
uvicorn.run(app, host="0.0.0.0", port=8001, reload=False)


启动命令必须在 `river-ai` 根目录下用模块方式运行：

powershell
cd d:\河道治理\river-ai
python -m services.main


 12.7 端口被占用

**查端口占用**：
powershell
netstat -ano | findstr ":8084"
 找到 PID 后
Stop-Process -Id <PID-Force


各服务默认端口：

| 服务 | 端口 |
|------|------|
| river-server | 8084 |
| river-admin | 5173 |
| river-dashboard | 5174 |
| river-ai | 8001 |
| MySQL | 3306 |

 12.8 前端 API 地址不对

如前端调用后端 404，检查 [river-admin/src/api/index.ts](./river-admin/src/api/index.ts) 和 [river-dashboard/vite.config.ts](./river-dashboard/vite.config.ts) 的代理配置，确保指向 `http://localhost:8084`。

 12.9 数据库连接失败

　　　1.确认 MySQL 已启动（phpStudy 或服务）
　　　2.确认 `river_governance` 数据库已创建
　　　3.用 Navicat 测试连接 `localhost:3306` root/root
　　　4.检查 [application.yml](./river-server/src/main/resources/application.yml) 配置

 13. 停止服务

 13.1 命令行启动的服务

按 `Ctrl + C` 即可停止。如果是后台进程，用命令 ID 停止（本工具场景）。

 13.2 查找并停止 Java 进程

powershell
 查找
Get-Process -Name java -ErrorAction SilentlyContinue | Select-Object Id, ProcessName, StartTime

 停止
Stop-Process -Name java -Force


 13.3 查找并停止 Node 进程

powershell
Get-Process -Name node -ErrorAction SilentlyContinue | Stop-Process -Force


 13.4 停止 MySQL

powershell
Stop-Process -Name mysqld -Force

powershell
 start-all.ps1 - 智河通平台一键启动脚本
 使用方式：powershell -ExecutionPolicy Bypass -File start-all.ps1

$ErrorActionPreference = "Continue"

 1. 设置环境

$env:Path = "$env:JAVA_HOME\bin;$env:Path"

 2. 启动后端（后台）
Start-Process -FilePath "java" -ArgumentList "-jar", "d:\河道治理\river-server\target\river-server-1.0.0.jar" -WorkingDirectory "d:\河道治理\river-server"
Write-Host "后端服务启动中（8084）..."

 3. 启动 AI 服务（后台）
Start-Process -FilePath "python" -ArgumentList "-m", "services.main" -WorkingDirectory "d:\河道治理\river-ai"
Write-Host "AI 服务启动中（8001）..."

 4. 启动管理后台（后台）
